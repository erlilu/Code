# 异常
> 异常不同于错误，解释器可以执行，能够通过异常处理机制解决 

## 常见的异常分类
1. ZeroDivisionError: 当除数为 0 时触发。
2. TypeError: 当操作的数据类型不正确或不兼容时触发。
3. AttributeError: 当对象没有制定的属性或方法时触发。
4. IndexError: 当索引超出范围（索引越界）时触发。
5. NameError: 当使用了不存在的变量时触发。
6. KeyError:当访问字典中不存在的key时触发。
7. ValueError: 当值不合法，但类型正确触发。

## 异常处理
1. 不是让异常消失，而是将异常捕获，随后根据异常的具体情况，来执行制定的逻辑。
2. 初级处理
   - 将可能出现异常的代码放在try中，出现异常后的处理代码写在except中。
   - 如果try中的代码出现异常，那try中的后续代码将不会执行，并自动跳转到except中处理异常。
   - 如果try中的代码没有异常，那except中的代码就不会执行。
   - 无论时否发生异常，try-except 后面的代码都会继续执行。 、
3. 异常处理（捕获制定的类型的异常） 
   - 根据python的异常文档，异常存在继承关系。多个except从上向下匹配，匹配成功后不再继续。【详情请看官方文档】
4. 异常处理的完整写法：
   - try: 尝试去做可能出现异常的事情
   - except: 出现异常时的处理(出现异常时如何补救)
   - else: 如果一切顺利(没有异常)要做的事情
   - finally: 无论有没有异常，都要做的事情

## 自定义异常类
1. 由开发人员自己定义一个异常类，用来表示代码中“更具体、更有业务含义”的异常。
2. 具体规则：定义一个类（类名通常以Error结尾），继承Exception类或它的字类。
